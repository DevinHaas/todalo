## Notes (8 Nov 2026)

- **Data model (migration 0033, additive, applied):** `coach_provider_configs` holds one configuration per user and kind (primary key user + provider), with the same columns and AES-256-GCM sealing as `coach_providers`. `coach_settings.active_provider` holds the user's pick (a kind or `chatgpt`). The ticket-17 row in `coach_providers` is never rewritten: `getCoachState` reads it as its kind's configuration until the new table has one for that kind. Disconnecting that kind deletes both rows (the user's own action). The ChatGPT sign-in stays in `coach_chatgpt`. A new sign-in resets its `created_at`, so the sign-in counts as configured then; token refreshes do not.
- **Selection (`pickCoachProvider` in `packages/server/src/coach.ts`, pure and table-tested):** the pick if it is still configured, else the most recently configured. If that one cannot run (a ChatGPT sign-in whose refresh OpenAI refused, or a key that no longer decrypts), the most recently configured provider that can run takes over. `GET /coach` returns `selected` (the pick) and `provider` (what runs), so the picker shows a quiet note when they differ. `getCoachProvider` (explanations, drafts) is unchanged for callers.
- **API:** `PUT /coach/provider` saves that kind (an omitted key keeps that kind's own key). `DELETE /coach/provider?provider=<kind>` disconnects one; without the parameter it removes every keyed provider, as before. `POST /coach/provider/test?provider=<kind|chatgpt>` tests a card; without it, the active provider. New: `PUT /coach/active { provider }`, 404 unless configured. `CoachDto.keyProvider` was replaced by `providers` and `selected`. ChatGPT routes and Tauri commands are unchanged.
- **Tauri:** `disconnect_coach` and `test_coach` take an optional `provider`, checked against the known kinds before it becomes a query string. There is a new `set_coach_active` command, with its permission (`allow-set-coach-active`, autogenerated file) and capability entry.
- **UI:** a card per provider (lucide marks on `--color-provider-*` tokens, light and dark), with Configure/Manage opening the form inline. This avoids a dialog inside the Settings dialog, and keyboard targets stay inside `[data-coach-settings]`. The "Coach model" pill is a `DropdownMenu` radio group. It lists configured providers in card order and disables one that cannot run. Test connection sits beside it (Alt+Shift+T).
- **Keyboard:** Alt+Shift+M (`coach.next-provider`) makes the next provider that can run the active one, with a toast. It works everywhere, Settings included. Alt+Shift+C and Alt+Shift+Q open the ChatGPT card first when it is closed.
- **Left out:** runtime fallback inside a single model call. A provider that answers 401 mid-request is not retried on another provider; the fallback is decided when the provider is resolved, as in ticket 18. Add it in the `model` seam if bad keys turn out common.
